# Testbed corpus tooling

This directory holds the tooling that captured the frozen testbed corpus, the 10,908 benign and
10,228 attack rows of `data/corpus/labelled/testbed.parquet`. It is real HTTP traffic
against running crAPI and VAmPI instances, recorded by a mitmproxy reverse proxy, with attacks
from sqlmap, ffuf with SecLists, nuclei, hydra and a curated payload set, and benign traffic from
scripted clients. Reproducing the paper does not require running any of it: the frozen corpus is
downloaded by `scripts/fetch_data.sh corpus`, and a live re-capture produces an equivalent but
not identical corpus.

## How labels are assigned, never from request content

1. `mitm_addon/capture_addon.py` records every flow with the client IP the proxy sees. It assigns
   no labels and inspects no content.
2. Every generator, benign or attack, runs from its own static IP on the `corpus_net` Docker
   network and writes a campaign manifest: family, tool, source IP, time window.
3. `label/labeller.py` sets `label`, `attack_family` and `attack_tool` by matching each flow's
   source IP and timestamp into a campaign window. It imports only the standard library and
   pandas, and the verifier checks that by parsing its AST.

The manifests of the frozen corpus are in `docs/corpus/manifests/`. Each content family is
generated by at least two tools, and the curated payloads in `attacks/custom_inject.py` are
disjoint from the SecLists lists ffuf uses at commit `e5e49caa6fb648476f3bca391b26a45a4f5d3f13`,
so the cross-tool holdout does not leak. All tools draw User-Agents from one pool. The
`bola_idor`, `mass_assignment` and `business_logic_abuse` families look legitimate in any single
request and are labeled from the script's intent.

`run_smoke.sh` drives VAmPI with one benign and one sqlmap campaign to validate the pipeline;
`run_full.sh` runs the full capture, labeling and verification. Both need Docker with the images
pinned in the compose files, a SecLists checkout, and crAPI.
